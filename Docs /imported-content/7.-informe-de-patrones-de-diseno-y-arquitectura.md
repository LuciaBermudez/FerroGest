## Introducción y Alcance del Sistema

El presente documento describe los patrones de diseño tanto de interfaz UI como de arquitectura de software seleccionados para el desarrollo del sistema de información de la ferretería. El proyecto está diseñado para funcionar como una aplicación web centralizada, construida con una arquitectura moderna basada en componentes y servicios desacoplados.

Para cumplir con los requerimientos del proyecto, se definió el siguiente stack tecnológico:

* **Frontend:** React, organizado mediante componentes reutilizables.
* **Backend:** Node.js con JavaScript creando una API REST para procesar la lógica de negocio.
* **Base de Datos:** MySQL para el almacenamiento relacional de inventarios, usuarios y transacciones.

## Patrones de Diseño de Interfaz de Usuario (UI Design Patterns) Aplicados en el Mockup

Durante la conceptualización y diseño de las pantallas del sistema, se aplicaron diversos patrones de interfaz para garantizar una navegación intuitiva y eficiente para los operadores y administradores:

* **App Shell/Barra de Navegación Superior Persistente:** Aplicado en el encabezado azul superior que mantiene fija la marca del software y el menú principal de módulos como Dashboard, Inventario, Ventas, Clientes y Configuración, permitiendo cambiar de sección en un clic sin perder la ubicación actual.
* **Patrón de Tarjetas de Indicadores Clave/KPI Summary Cards:** Aplicado en las tarjetas superiores que muestran el resumen en tiempo real, destacando métricas como los SKUs activos en catálogo y la valorización consolidada.
* **Patrón de Búsqueda Dinámica y Filtrado Combinado/Search & Filter Pattern:** Aplicado en la barra de búsqueda por código de barras, SKU o descripción, junto con el selector desplegable de categorías y las opciones de exportación, agilizando la localización de los productos de la ferretería.
* **Patrón de Tabla de Datos Paginada con Alertas Visuales/Paginated Data Grid & Status Highlighting:** Aplicado en la tabla central que lista los productos con su código SKU, especificación, categoría, existencias y precios, incorporando paginación inferior y resaltado en color rojo para alertar existencias críticas, tal como se evidencia en el producto SKU-44109.
* **Patrón de Tarjetas de Acción Contextual/Actionable Insight Cards:** Aplicado en los paneles inferiores del sistema: Acción Inmediata Sugerida, balance de existencias físicas y conteo rápido, permitiendo ejecutar operaciones directamente desde las alertas de inventario.
* **Patrón Maestro-Detalle/Master-Detail:** Implementado en el módulo del Punto de Venta, donde el catálogo general actúa como la vista principal y el panel lateral derecho desglosa de forma dinámica el detalle de la compra activa, el subtotal y los métodos de pago.
* **Patrón de Contenedores y Tarjetas/Card Layout:** Utilizado para estructurar de manera limpia los formularios de autenticación y los bloques de analíticas, separando visualmente la información operativa de la interfaz general.

## Patrones a Nivel de Arquitectura del Software/Backend y Base de Datos

Aunque los patrones anteriores se ven reflejados en el diseño de Figma, por debajo el software implementa una estructura lógica para conectar las tecnologías elegidas:

* **Arquitectura Cliente-Servidor:** React corre en el navegador del cliente, es decir, la computadora de la ferretería o la caja registradora, y se comunica mediante peticiones HTTP (API REST) con el servidor backend desarrollado en Node.js y Express.
* **Patrón de Capas (Layered Pattern) en el Backend:** El servidor de Node.js se organiza separando las rutas, los controladores con lógica de negocio y las consultas SQL a la base de datos MySql, lo que mantiene el código ordenado y facilita corregir errores o escalar el sistema a futuro.

## Conclusión

La elección de estos patrones de diseño permite que el sistema de información sea intuitivo para el personal de la ferretería y fácil de programar para nosotros como desarrolladores. Al usar React con una estructura modular y una base de datos relacional en MySQL, garantizamos que el software responda rápido, maneje bien los datos de inventario en tiempo real y sea coherente con lo que diseñamos inicialmente en Figma.
